### Map precipitation frames (drawn on the server)

The worker draws the Map page's precipitation every 10 minutes (`backend/snowwatch/precip.py`, `snowwatch precip` by hand). Each frame is one palette PNG over a box around the active locations (Web Mercator, 1400 px wide, ~40 KB), listed in `data/precip/index.json` and served at `/api/precip` and `/api/precip/<name>.png`. File names include a hash of the pixels, so browsers cache them for good. The browser downloads the whole timeline once (~2 MB) and swaps frames on one canvas, which keeps scrubbing instant and phone memory low. Earlier versions stitched and repainted tiles in the browser, which was slow and crashed iOS Safari.

A frame is only redrawn when its inputs change: a new radar scan, a new HRDPS run (`reference_time`), or a new HRRR run for that hour. A cold build takes about 80 s (two frames at a time, peak ~350 MB); an unchanged pass takes about 2 s.

- **Radar (past ~2 h, 10-min frames):** RainViewer public API, `weather-maps.json`, scheme 2 with snow (`2/1_1`), tiles at zoom 7. Its published colour table (rainviewer.com/api/color-schemes.html) gives one colour per dBZ for rain and for snow. Each pixel becomes a rate: rain via Marshall–Palmer (Z = 200R^1.6), snow via Z = 180S^2. `nowcast` is empty, so there are no future frames.
  - Not used: MSC GeoMet `RADAR_1KM_RRAI` / `RSNO`. They're the same echoes converted with rain and snow formulas, not a type split.
- **Forecast, Canada and northern US (hourly, ~48 h):** MSC GeoMet WMS (`geo.weather.gc.ca/geomet`), HRDPS 2.5 km, `HRDPS.CONTINENTAL.DIAG_{RN,FR,SN}_PT1H` (mm in the hour ending at `time`). One GetMap per layer for the whole box, styled by an SLD in `sld_body` (each `ColorMapEntry` is a band's lower bound; below the first is transparent). Only one layer per request. The domain reaches about 42–44°N in the West. Free, no key, Open Government Licence – Canada.
- **Forecast, rest of the US:** clipped to outside the HRDPS domain (mask = `DIAG_PR_PT1H` styled solid).
  - NOAA HRRR simulated radar by type, from Iowa State's IEM tile cache, `cache/tile.py/1.0.0/hrrr::REFP-F{minute}-0/{z}/{x}/{y}.png`. Each minute slot comes from the newest run reaching it (hourly runs to 18 h, 6-hourly to 48 h). `data/gis/images/4326/hrrr/refp_{minute}.json` gives its valid time and run. Missing slots answer slowly with 503, so tiles aren't retried and one probe tile decides. IEM's palette families (greens/yellows rain, blues snow, purples/reds ice) map onto ours by lightness.
  - Where HRRR has nothing: NWS WPC 6-hour QPF, `mapservices.weather.noaa.gov/vector/rest/services/precip/wpc_qpf/MapServer` layers 13–25 (hours 0–6 … 72–78 from layer 13's `start_time`, UTC), fetched as GeoJSON and drawn in tan, with no type.
  - Not used: the NDFD WMS (days stale when checked, Nov 2026).
- **Base map:** Esri World Topo, dimmed in the dark theme. Its tiles have a lighter last row and column, so the map stretches each tile a pixel and clips that edge off.
- **Later option:** our own HRRR from NOAA's GRIB files on AWS (rain/snow/freezing rain/sleet and rate, to 48 h) would replace the IEM/WPC part of `precip.py`.
