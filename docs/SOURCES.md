### Map precipitation layers (browser only)

The Map page loads these straight from the browser; the backend never touches them. Base map: Esri World Topo (`server.arcgisonline.com/.../World_Topo_Map`), dimmed by a CSS filter in the dark theme. Its tiles have a lighter last row and column, so the map stretches each tile a pixel and clips that edge off. They play as one timeline (past 2 h → next ~48 h) in one set of colours: rain, mix/ice and snow ramps by rate (`frontend/src/lib/radar.ts`).

- **Radar (past ~2 h, 10-min frames):** RainViewer public API, `weather-maps.json`, scheme 2 with snow (`2/1_1`), CORS open, detail to zoom 7. No future frames (`nowcast` is empty). Its published colour table (rainviewer.com/api/color-schemes.html) gives one colour per dBZ for rain and for snow, so the browser reads each pixel back to dBZ and type and repaints it: rain via Marshall–Palmer (Z = 200R^1.6), snow via Z = 180S^2.
  - Not used: MSC GeoMet `RADAR_1KM_RRAI` / `RSNO`. They cover North America, but they're the same echoes converted with rain and snow formulas, not a type split.
- **Forecast, Canada and northern US (hourly, ~48 h):** MSC GeoMet WMS (`geo.weather.gc.ca/geomet`), HRDPS 2.5 km, `HRDPS.CONTINENTAL.DIAG_{RN,FR,SN}_PT1H` (rain, freezing rain, snow water equivalent; mm in the hour ending at `time`). Free, no key, CORS open, Open Government Licence – Canada. The domain reaches about 42–44°N in the West (not CO, UT, CA). One layer per request; colours go in `sld_body`, where each `ColorMapEntry` is the lower bound of its band and values below the first are transparent. It answers 429 when hit hard, so we ask for 1024 px tiles. The map loads the rest of the timeline in the background, two frames at a time, so scrubbing hits the browser cache (GeoMet sends `max-age=3600`, IEM 300 s, RainViewer two days).
- **Forecast, rest of the US:** drawn on canvases and clipped to outside the HRDPS domain (mask = `DIAG_PR_PT1H` styled solid).
  - NOAA HRRR simulated radar coloured by type, from Iowa State's IEM tile cache: `cache/tile.py/1.0.0/hrrr::REFP-F{minute}-0/{z}/{x}/{y}.png`, CORS open. Each minute slot comes from the newest run that reaches it (hourly runs to 18 h, 6-hourly runs to 48 h). `data/gis/images/4326/hrrr/refp_{minute}.json` gives the slot's valid time, so we check it. The browser maps IEM's palette families (greens/yellows rain, blues snow, purples/reds ice) onto ours by lightness. IEM sometimes answers errors without CORS headers, so lookups retry once.
  - Where HRRR has nothing: NWS WPC 6-hour QPF, `mapservices.weather.noaa.gov/vector/rest/services/precip/wpc_qpf/MapServer` layers 13–25 (hours 0–6 … 72–78 from layer 13's `start_time`, UTC). We fetch the polygons as GeoJSON (CORS open) and draw them in tan, with no type. The service ignores custom renderers (`dynamicLayers` draws nothing).
  - Not used: the NDFD WMS (`digital.weather.gov/ndfd/wms`), whose data was days stale when checked (Nov 2026).
- **Later option:** our own HRRR tiles (NOAA's HRRR GRIB on AWS, categorical rain/snow/freezing rain/sleet plus rate, to 48 h) would replace the IEM/WPC source in `southLayer.ts` for full type everywhere in the US.
